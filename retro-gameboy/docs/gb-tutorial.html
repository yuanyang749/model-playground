第 1 章：Android Termux 本地基石环境搭建

1.1 依赖安装与 AArch64 配置

切勿使用 Google Play 商店版 Termux（已停更）。必须从 GitHub Releases 下载最新的 arm64-v8a 版本。

# 1. 换源并升级基础包
pkg update -y && pkg upgrade -y

# 2. 安装核心套件
pkg install -y nodejs-lts python git curl build-essential python-pillow

# 3. 申请存储权限
termux-setup-storage

1.2 Termux 黄金“避坑四准则”

严禁 sudo
Termux 无 root，提权必须走 Shizuku 的 rish 工具。
严禁 systemd
后台服务一律使用 nohup 或守护进程。
严禁 PC 桌面音频
不可用 ALSA，音频一律调用 Web Audio API。
严禁 apt-get / snap
包管理一律使用 pkg install。

1.3 Antigravity CLI 安装与 PATH 避坑

# 1. 一键安装
curl -fsSL antigravity.google/cli/install.sh | bash

# ⚠️ 关键避坑：Termux 默认 PATH 无 ~/.local/bin，需手动追加
echo 'export PATH="/data/data/com.termux/files/home/.local/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc

# 2. 启动智能体
agy

配置 GEMINI.md（放在 ~/.gemini/antigravity-cli/GEMINI.md），让智能体时刻牢记自己运行在 Android 手机上，输出移动优先代码。

第 2 章：突破沙盒瓶颈 —— Shizuku (`rish`) 提权指南

2.1 为什么 Termux 需要 Shizuku

Termux 作为普通 App 沙盒，无法访问 /sdcard/Android/data，也无法截屏或模拟触控。Shizuku 基于 Android 系统级 ADB 提权，提供具备 shell 用户与 ext_data_rw 权限的 rish 终端通道！

2.2 部署 rish 核心步骤

  1. 开启手机“开发者选项”与“无线调试”；
  2. 在 Shizuku App 中点击“配对”并启动服务；
  3. 在 Termux 中部署 rish：
# 导出 rish 文件
pkg install -y termux-tools
# 赋予执行权限并测试
chmod +x ~/bin/rish
rish -c "id"
# 输出 uid=2000(shell) 即提权成功！
⚠️ Android 14 关键坑点
Android 14 强化了子进程派生限制，在 Termux 运行 rish 前，确保在手机系统“应用详细信息”中允许 Termux 在后台无限制运行并关闭电池优化。

第 3 章：真机自动化与视觉排障全景对比

方案 A: Termux:API
轻量获取电量/传感器，但无法截取系统屏幕。
方案 B: Shizuku + rish (推荐)
极速截屏 (screencap) 与模拟点击 (input tap)。
📸 截屏黑屏故障复盘
当手机锁屏时，Android SurfaceFlinger 会触发 FLAG_SECURE 保护机制，screencap 截出的文件仅 15KB 全黑。只有在屏幕解锁亮屏状态下，才能捕获真实绚丽色彩！

第 4 章：实战案例 —— 纯手机研发 Game Boy 掌机与多合一游戏合集

  • 防误触多指触控追踪：隔离 activeTouchId，绝不出现双手按键互相串号；
  • 震动反馈（Haptic Feedback）：开火与撞击触发真实微震动。

4.2 向量解耦算法（防卡死死锁）

当两辆坦克碰撞时，传统网格法会导致双方坐标重叠且无法向反方向移动（死锁）。我们引入向量解耦推离算法：

// 向量解耦：计算两坦克中心向量并互相推离
const dx = tankA.x - tankB.x;
const dy = tankA.y - tankB.y;
const dist = Math.hypot(dx, dy) || 1;
const overlap = (tankA.size / 2 + tankB.size / 2) - dist;
if (overlap > 0) {
  tankA.x += (dx / dist) * (overlap / 2);
  tankB.x -= (dx / dist) * (overlap / 2);
}

第 5 章：联动 MT 管理器 MCP 服务打造掌上工作台

5.1 什么是 MT 管理器 MCP 服务

MT 管理器作为 Android 上的逆向神器，最新版内置了 Model Context Protocol (MCP) 服务！

⚡ 同机回环直连的绝对优势
智能体运行在 Termux，MT 管理器运行在同一台手机，通过 http://127.0.0.1:8787/mcp 本地回环直连，延迟低于 1ms，无公网泄露风险！

5.2 49 项逆向工具赋能六大场景

  • APK 静态分析：查看清单、解析签名、检索方法交叉引用（XREF）；
  • DEX 与字节码审查：反编译类轮廓，精准分析 Smali；
  • Native SO 逆向：反汇编机器码，自动生成函数控制流图 (CFG)；
  • 自动化打补丁：内存机器指令 Patch、替换资源与重新打包签名。

5.3 配置模板与 Token 鉴权说明

在 MT 管理器中开启 MCP 服务后，建议开启安全认证以防止本地恶意应用越权访问。将界面显示的端口（如 8787）与 Token 填入全局配置：

{
  "mcpServers": {
    "mt-manager": {
      "url": "http://127.0.0.1:8787/mcp",
      "//_comment": "若在 MT 管理器开启了认证（推荐），需配置 headers",
      "headers": {
        "Authorization": "Bearer 您的MT_MCP_TOKEN"
      }
    }
  }
}
